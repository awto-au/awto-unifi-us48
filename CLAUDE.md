# CLAUDE.md — awto-unifi-us48

Mainline Linux port + RE for the UniFi US-48-500W. Target: native mainline (`scripts/build_mainline.py`, `mainline/`). OpenWrt was removed 2026-11-18 (Dan: only noise); last state in tag `openwrt-parked` (#74). **Public repo** — no secret values (filesystem paths + device IDs are fine), no backups/firmware images, except the BCM59111 PoE firmware (`hwdb/firmware/`, Dan 2026-11-21). SDK source + derived register tables ARE fine to commit (Dan 2026-10-14).

- Entry point `scripts/dev.py` (`describe` lists every command; `doctor`, `console`, `send`, `boot-ram`, `flash-net`, `boot-flash`). Console = one visible tio window; scripts use its socket, never the tty. Adapter is local on Selwyn since 2026-11-14 (leave `US48_HOST` unset; set `US48_HOST=lizard` only if it moves back).
- Build: `python3 scripts/build_mainline.py` (kernel + modules: Fedora `arm-linux-gnu-gcc`; rootfs `mainline/rootfs/` via `scripts/build_rootfs.py`: busybox + dropbear, static musl). No OpenWrt anywhere (tag `openwrt-parked`). Details: `docs/mainline.md`.
- Source trees from machine-shared stores, never fresh clones (#45): `tmp/linux-mainline` = worktree of the Linux store (`tmp/linux-store`). Gitignored symlinks into `/mnt/1tnvme/git-mirrors`; never `git gc` in a store.
- Facts in `docs/`; findings + open questions in GitHub issues. Hardware facts (addresses, registers, ports, firmware functions) live in `hwdb/` (schema `docs/hwdb.md`); generated headers/tables, never copy by hand.
- Device: dev/test unit (it powered 5 PoE cameras on stock; not the house uplink, Dan 2026-11-16; Dan says still test), recovery via serial + JTAG, full-flash backups. Test images go in backup slot `kernel0` (`scripts/dev.py flash-kernel0` / `boot-flash`). Never write `kernel1` (stock), the bootsel record (`0x1ee0000`), `u-boot`, `EEPROM`; never `saveenv`; don't guess GPIO/I2C/SPI writes. u-boot-env: only the docs/autochain.md image (Dan 2026-11-15).
- **Module changes: no reboot (Dan 2026-11-19).** Test loadable-driver changes by copying the rebuilt `.ko` to the running board and reloading it (`scripts/mod_reload.py`, `lx.py --put`). RAM-boot / reboot / power cycle only when the kernel itself changed (DT, defconfig, built-in code, kernel patch): diff the branch first and name the change that forces it. Flashing is a separate step after the module tests pass.
- **Board tests are scoped to the change (Dan 2026-11-19).** Test only what the change can affect: LED, fan, board-IO, sensor, PoE-read-only changes = that subsystem's own checks plus one sanity line (board reachable, fans quiet). The full regression (`switchdev_test`, `stp_loop_test`, `route_nat_fw_test`, `copper_check`, module reloads, self-test) only when the change touches the datapath: `us48_cmic` core, DMA/rings, TSC/SerDes, PHY, switch tables, VLAN/bridge code, or a new kernel. No before/after re-reads of unrelated registers, no "run everything" by default; name in the brief why each check is there.
- Fans: presets only (50/70/90/100 %), no tach, no off. Quiet rule default (Dan 2026-11-16), 100 % switchable (`US48_FAN_BOOT_LEVEL`, `us48_fan.level`/`quiet`), see `docs/fan.md`; drivers `kernel/us48-fan` + awto-uboot `fan.c` — watch temperature on every boot. PoE is ON at boot, all 48 ports (Dan 2026-11-21): `S06us48-poe` loads `bcm59111 fw_load=1 enable_ports=all`; kill switch `us48-poe-off`.
- Lab topology shared with sw1/sw2 (units, serial adapters, inter-unit cabling, protected ports): awto-dan `docs/lab/lab.toml`, read via vendored `scripts/_lab.py` (`scripts/sync_shared.py check`); never copy those facts here or into hwdb.
- Backups + stock firmware images stay out of git under `tmp/` or `private/`.
