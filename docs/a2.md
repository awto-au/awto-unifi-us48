# a2: the unit 1 (BCM53346) Cortex-A9

Names: a1 = unit 0 A9 (BCM53344, the host SoC running Linux/uboot-2), a2 = unit 1 A9 (BCM53346, PCIe endpoint). Same die family (CHIPID 0x3f00db56 on both), different bonding/strap. Evidence and probe log: issue #53. Memory facts: [sram.md](sram.md).

## State of a2 on this board (C, probes 2026-11-13)
- Out of reset, powered, debug authorised (`AUTHSTATUS` 0xff). It idles in the boot ROM spin loop (BOOT_DEV 0 -> QSPI XIP at 0x1c000000; unit 1 has no flash, window reads zero).
- Nobody in stock (switchdrvr, BDE, U-Boot) uses it.
- 16 KiB SRAM at 0x1b000000 (same as a1). No DDR known. Host RAM reachable through PAXB outbound windows.

## How the host reaches unit 1
- BAR0 (32 KB, `0000:01:00.0` resource0): PAXB registers at +0x2000.., Chipcommon page at +0x0.
- Data window: PAXB `IMAP0_7` (BAR0+0x2c1c, host-writable, default 0x18032001) selects a 4 KiB AXI page, visible at BAR0+0x7000. `IMAP0_1` ignores writes.
- Outbound (a2 -> host RAM): `OARR_0` (BAR0+0x2d20) = 0x08000001 with `OMAP_0` (BAR0+0x2d40/44) = 0 maps a2 AXI 0x08000000.. to host physical 0x0..; must stay inside 0x08000000-0x0fffffff (other ranges hit the unused DDR controller and stall a2).

## Starting code on a2
1. Write the stub (`tools/a2_stub.S`, 196 bytes) into SRAM through the window.
2. CoreSight: unlock (`LAR` 0xC5ACCE55), `DSCR.HDBGen`, `DRCR` halt, `DSCR.ITRen`, `DTRRX` = 0x1b000000, ITR `mrc p14,0,r0,c0,c5,0` + `mov pc,r0`, restart.
3. Stub serves a mailbox at 0x1b000100: cmd 1 call, 2 read32, 3 write32; payload area 0x1b000200, stack top 0x1b003ff0.
- Undo / recover a hung a2: pulse `CRU_CONTROL` (AXI 0x1803e000) bit 4 low then high; a2 returns to the ROM loop.
- ROM entry: a2 does not take the "boot from PCIe" path on a plain ARM reset (see issue #53); the debug start above is the working route.

## Tools
- `rust/a2ctl` (native on a1 under OpenWrt, target `armv7-unknown-linux-musleabi`): reset, start, status, read, write, load, call, run, axi-read/axi-write (host path to any unit-1 AXI address), i2c-scan, bar-read. A stub command round trip is ~25 us.
- `scripts/a2_loader.py` (same operations through the uboot-2 console, ~0.3 s each), `scripts/a2_force_pc.py`, `scripts/a2_bench.py`, `scripts/mdio_scan_u1.py`, `tools/a2_bench.S`.

## What a2 can run from (measured)
- SRAM 16 KiB; host RAM via OARR_0 at cached speed once the L1 I-cache is on (loop: 5.5 ticks/iteration from both). Uncached host RAM data is slow (PCIe round trip). Switch packet buffers/tables are S-channel only, not executable. Details and numbers: [sram.md](sram.md).
- L2 as RAM (PL310 lockdown, 128 KiB at 0x50000000) is the planned fast data store (NAT state, #40); needs MMU on a2.

## Unit 1 peripherals seen so far
- MDIO: 16 integrated GPHYs + 8 external octal PHY ports = front 25-48; see [hardware.md](hardware.md).
- CCB I2C (0x18038000, 0x1803b000): registers live, probe never completes (inconclusive). No flash on QSPI. GPIO in 0xfc3. No pin-mux registers in the regdb.

## Open
- Entry via the boot ROM PCIe path (BOOT_DEV = 7 via `DMU_PCU_IPROC_STRAPS_SW_OVERRIDE`): status word follows the override, a2 did not take the path after a core reset.
- Rust `no_std` firmware for a2 (target `armv7a-none-eabi`), MMU + L2-as-RAM, then useful work (NAT/packet offload).
