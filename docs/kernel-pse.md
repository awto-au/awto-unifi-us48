# Stock kernel: PSE platform driver, board code, gpiodev

Offline RE of stock 7.5.15 kernel (Linux 3.6.5, ARM, VA base `0xc0018000`) and `gpiodev.ko`. Ghidra text exports + ARM disassembly + literal-pool/data reads (`scripts/elf_peek.py`).
Legend: **C** = confirmed (evidence cited), **I** = inferred.
Complements `docs/board.md` (switchdrvr side; its PSE IRQ table matches section 1.2).

## 0. Summary

- Kernel PSE driver = IRQ-to-netlink forwarder only. Touches no I2C/SPI/GPIO output. (C: `pse_plt_probe` `0xc0265fc0`, work fns `0xc0023e14..0xc0023e4c`)
- All PoE control (BCM59111 I2C, enable, firmware load) is userspace. Kernel only says "which PSE group raised its interrupt".
- Kernel has **no I2C bus driver, no i2c-dev, no registered i2c_board_info** (C, section 4).
- `gpiodev.ko` `gpio_set_poe` is a stub returning 0 on this build; `/proc/gpio/poe_passthrough` does nothing (C).
- One GPIO chip (CCA, `GPIOA`): Linux GPIO 4..15 = HW pins 0..11. PSE uses pins 0, 1, 8; reset button pin 11; status LED pins 6, 7.

### 1.2 GPIO / IRQ lines

GPIO chip `GPIOA` (section 2.1): `to_irq(gpio) = 256 + (gpio - 4)`. IRQ flags passed to `request_threaded_irq` = `2` (falling edge); no thread fn, so handler runs hard-IRQ.

| Name (IRQ string) | Linux GPIO | CCA pin | Linux IRQ | Handler | Work fn → event type | Ev |
|---|---|---|---|---|---|---|
| `pse_master_int` | 12 | 8 | 264 | `pse_master_irq` `0xc0023df4` | `pse_master_work` `0xc0023e4c` → 1 | C |
| `pse_slave_int` | 5 | 1 | 257 | `pse_slave_irq` `0xc0023dd4` | `pse_slave_work` `0xc0023e30` → 2 | C |
| `pse_alarm_int` | 4 | 0 | 256 | `pse_alarm_irq` `0xc0023db4` | `pse_alarm_work` `0xc0023e14` → 0 | C |

- Probe order: master, slave, alarm. Slave and alarm are optional (slave skipped if its GPIO word is 0). Failure frees earlier IRQs. printk "pse_platform: failed to request pse master/slave/pse_alarm irq". (C)
- Probe does **not** configure pin direction/pull/mux; relies on `request_threaded_irq` + CCA `set_type`. No `gpio_request`. (C: no gpio_* calls in probe)
- Edge is from CCA event registers (`iproc_gpio_irq_set_type` `0xc00260cc`, edge types use regs at +0x24/+0x1c from `0x18000060`). (C for falling flag; register role I)
- Roles: master = PoE card 0 (ports 1-24), slave = card 1 (25-48), alarm = log only, per switchdrvr dispatch in `docs/board.md`. (I from there)

### 1.3 IRQ handling

- Handler: `disable_irq_nosync(irq)`, `schedule_work(...)`, return `IRQ_HANDLED`. (C)
- Work fn: `pse_nl_port_evt_unicast(type)`, then `enable_irq(irq)`. (C)
- Re-arm happens right after the unicast, with no I2C ack in the kernel. Pin is falling-edge: a line still low after re-enable gives no new edge, so userspace must clear the BCM59111 interrupt over I2C. (I)

### 1.4 Generic netlink: `PSE_FAMILY`

| Field | Value | Ev |
|---|---|---|
| Family name | `PSE_FAMILY` | C (struct `0xc0f0622c`) |
| id | `GENL_ID_GENERATE` (0, dynamic; resolve by name via ctrl family) | C |
| version / maxattr / hdrsize | 1 / 3 / 0 | C |
| Multicast groups | none; unicast only | C |
| Ops table | `0xc0f06274`, 2 ops, policy `0xc0f062b4` | C |
| Attr policy | attrs 1, 2, 3 all `NLA_U8` | C |

Commands:

| cmd | Handler | Behaviour | Ev |
|---|---|---|---|
| 1 | `pse_register_rcv_nl` `0xc0024074` | stores sender portid in driver state (`0xc0f18d78`); logs "Received %d PSE boards registered with pid %d" where %d = attr 1 (u8). Errors: "genl_info error", "no info->attrs" | C |
| 2 | `pse_port_event_rcv_nl` `0xc0023fbc` | returns 0 (no-op) | C |

Event message (kernel → userspace), `pse_nl_port_evt_unicast` `0xc0023fc4`:
- skb 0xf54 bytes, GFP_ATOMIC-class (0xd0). Header via `genlmsg_put(pid=0, seq=++counter, flags=0, cmd=2)`. (C)
- One attribute: type 2, len 1, `u8` = source (0 alarm, 1 master, 2 slave). (C)
- Sent with `netlink_unicast` to the portid saved by cmd 1, flags `MSG_DONTWAIT` (0x40) on `init_net.genl_sock`. (C)
- Before any cmd 1, portid is 0 (kernel socket), so events are effectively dropped. (I)
- Userspace flow: open genl socket, resolve `PSE_FAMILY`, send cmd 1 with attr 1 = number of PSE boards (2 on this switch, per `docs/board.md`), then recv cmd-2 messages. (I)

### 1.5 `/proc/iproc-pse/enable`

- `show_pse_enable` `0xc0023e7c`: prints current state (0/1). (C)
- `proc_write_pse_enable` `0xc0023eb0`: reads <=7 bytes, first char only. `'1'` and currently 0 → `platform_driver_register(pse driver)` (probes `pse_plt`, requests the 3 IRQs). `'0'` and currently 1 → `platform_driver_unregister`. Anything else: ignored. (C)
- Module-exit stub `FUN_c0350700` also unregisters and removes the proc entries. (C)
- OpenWrt port: a replacement does not need this driver at all if the new PSE driver takes the three GPIOs/IRQs itself (pins 0, 1, 8 on CCA GPIO, falling edge). (I)

No functions named `ubnt*`, `led*`, `poe*`, `fan*`, `cpld*`, `sfp*`, `watchdog*` exist in the kernel image besides the PSE ones. No kernel watchdog driver. (C: grep of `funcs.tsv`)

Pin/mux: no pinmux/DMU-GPIO-select writes anywhere in the kernel; pin function is whatever U-Boot/reset leaves. (C: `northstar_dmu_init` body)

**GPIO chip** (struct `0xc0f0637c`, C):
- Type 0 = ChipcommonA, label `GPIOA`, Linux base **4**, ngpio **12**, IRQ base **256** (0x100), parent IRQ **123** (0x7b, shared).
- Regs `0x18000060..0x180000af` (in `+0`, out `+4`, outen `+8`; `0x18000064` = out, `0x18000068` = outen as used by gpiodev). Intr block `0x18000000`, DMU `0x18030000`.
- HW pin = Linux GPIO - 4 (offset used directly as bit index in `iproc_gpiolib_set/input/output`). IRQ = 256 + pin.
- No CCB (`GPIOB`) chip registered.

**SPI** (C): `qspi_iproc` master (regs `0x18027000` BSPI, `0x18027200` MSPI, CRU `0x1803e000`); one device `m25p80` on bus 1 CS 0, mode 3, 50 MHz (`0x02faf080`). Fallback partitions in pdata: `boot` 0xa0000, `env` 0x60000; stock cmdline `mtdparts` overrides (see `docs/hardware.md`). No other `spi_board_info`; no CPLD/IO-expander SPI device in the kernel. The "MSPI board IO" in `docs/board.md` is therefore not a Linux SPI client on stock. (C for absence of registration; transport I)

Platform devices in kernel: 8250 UART(s), `qspi_iproc`, `iproc_pmu_device`, `pse_plt`, plus `bcmiproc-cmicd` from `linux-kernel-bde.ko` (module). (C)

### 2.2 Modules loaded at boot (initramfs `init`)

`ubnt_framework`(absent), `ubnt_common`, `ubnthal`, `gpiodev` (then `echo 20 > /proc/gpio/led_pattern`), `linux-kernel-bde` (char 127), `linux-user-bde` (char 126). (C)

## 3. `gpiodev.ko`

Module: license Proprietary, depends `ubnthal` (uses `ubnthal_get_systemid`), vermagic 3.6.5. No exported symbols beyond `init_module`/`cleanup_module`; helper functions are local. Many are stubs on this build.

### 3.1 Functions

| Function | Addr | Behaviour | Ev |
|---|---|---|---|
| `gpio_set_poe` | `0x10000` | `return 0` (stub) | C |
| `gpio_init_led` | `0x10008` | ioremap `0x18000068` (CCA outen) and `0x18000064` (CCA out), sets outen bits 6,7 (`|= 0xc0`) | C |
| `gpio_set_led(v)` | `0x10060` | bit 0 → CCA out bit 7, bit 1 → CCA out bit 6 (RMW on `0x18000064`) | C |

| `gpio_reset_irq_setup` | `0x100a4` | picks reset-button IRQ from `ubnthal_get_systemid()`, `request_threaded_irq(irq, isr, flags=8, "reset")` | C |

## 4. Kernel I2C

- No I2C adapter driver in the image: `i2c_add_adapter` / `i2c_add_numbered_adapter` have **no callers** in vmlinux; no iProc SMBus / BSC strings; no `i2c-dev` driver; `i2c_register_board_info` has **no callers**. (C: `calls.tsv`, `strings.tsv`)
- `i2c_init` (`0xc034adc4`) is core-only (bus + driver registration).
- None of `ubnt_common`, `ubnthal`, `gpiodev`, `linux-kernel-bde`, `linux-user-bde` references an i2c adapter symbol (strings check). (C)
- `/dev/i2c-0`, `/dev/i2c-1` are static cpio nodes (see `docs/board.md`); with no i2c-dev in the kernel they are non-functional nodes (I). All PoE/sensor/SFP I2C goes through the switch chip's CMIC SMBus master from userspace (`docs/board.md`).
- Bus speeds, mux/PoE addresses, device table: `docs/board.md` (switchdrvr-derived); nothing kernel-side to add. (C)
- OpenWrt consequence: a normal Linux I2C master is needed (iProc SMBus `i2c-bcm-iproc` at `0x18008000` if present on HR2, or a CMIC-SMBus adapter); stock gives no hint. (I)
